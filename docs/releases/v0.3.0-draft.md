## What users gain

You can point a Chromium check at a running local application, receive a measured horizontal-overflow result, and keep the screenshot and JSON report from that run. The Japanese getting-started guide connects a reproducible broken/repaired example to your own application.

- `npm run check:ui -- --url http://127.0.0.1:3000/settings --ready-selector '[data-ui-ready]'`
- PASS exits 0, measured overflow FAIL exits 1, and execution ERROR exits 2.
- Each run saves separate Evidence under `ui-evidence/` by default. A page load or missing readiness condition cannot count as PASS.
- A synthetic Japanese notification-settings example shows 137px overflow before repair and zero after repair at a 412px viewport. README images have source commit/run provenance.
- [Getting started](../getting-started.md) covers installation, expected failure, repair, your own DESIGN.md and your own local app.
- [Coverage map](../validation-coverage.md) separates static metadata checks, shipped fixtures, local-app overflow checks and human review.

The command accepts explicitly supplied local HTTP(S) URLs; it does not discover pages or sign in. Page scripts and resource requests execute normally. Choose a readiness selector that identifies the intended application screen, especially when authentication exists.

## Maintenance updates included

- Playwright is pinned to 1.64.1 (v0.2.0 shipped 1.63.0).
- checkout, setup-node, upload-artifact and setup-python use v7.
- Strict contract validation, seven required fixtures, desktop/Pixel 7 Chromium gates and 14-day CI Evidence retention are preserved.

## Compatibility and limits

Existing DESIGN.md contracts remain the editable source; JSON is still a generated projection. The new command checks document-level horizontal overflow in Chromium at one requested viewport. Its default 412×839 viewport is a resized desktop context, not Pixel 7 emulation.

PASS does not establish whole-contract compliance, reading comfort, clipping safety, accessibility compliance, native IME operation or other-browser support. The regression suite deliberately includes clipped content that passes the document-overflow check to keep this limit visible.

The before/after example is a synthetic demonstration, not an independently observed production incident or an AI-versus-human comparison. Real-application onboarding remains follow-up work.

## Upgrade and rollback

For a main checkout, follow [the setup guide](../getting-started.md), install the pinned dependencies and Chromium, then run the example before targeting your own app. No existing DESIGN.md migration is required.

The rollback release is v0.2.0. Returning to it retains the original contract/fixture validation and removes access to the new local-URL command. Published v0.2.0 notes and tag remain unchanged.
