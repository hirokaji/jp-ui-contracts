# v0.2 Release Gate

This document defines the minimum evidence required before tagging `v0.2.0`.

The release goal is not visual perfection. The goal is to prove that the repository can turn a Japanese UI contract into **repeatable static and rendered checks** without creating a second hand-maintained contract source.

## Gate A — Contract integrity

All shipped contracts must pass strict validation:

- `templates/base/DESIGN.md`
- `templates/media/DESIGN.md`
- `templates/saas/DESIGN.md`
- `templates/docs/DESIGN.md`
- `templates/dashboard/DESIGN.md`
- `examples/sample-media/DESIGN.md`
- `examples/sample-saas/DESIGN.md`

Required evidence:

```bash
python validators/contract.py validate --strict ...
python -m unittest discover -s tests -p "test_*.py" -v
```

Release blocker:

- invalid locale / profile / review status
- missing validation targets
- a hard lint violation
- parser / validator unit test failure

## Gate B — P0 + P1 fixture completeness

The following fixtures must contain both a renderable `index.html` and finished PASS / WARN / FAIL criteria:

### P0

- `long-paragraphs`
- `mixed-script-headings`
- `long-url-overflow`
- `forms-ime-errors`

### P1

- `dense-tables`
- `mobile-wrap-stress`

`tests/test_fixture_manifest.py` enforces that these fixtures exist and do not contain unfinished `TBD` criteria.

Release blocker:

- missing fixture page
- missing PASS / WARN / FAIL section
- unfinished P0/P1 criteria
- fixture page missing `lang="ja"` or its `data-fixture` identity

## Gate C — Rendered validation

Playwright renders all P0/P1 fixtures in two Chromium projects:

- desktop Chromium at 1440px width
- mobile Chromium using the Pixel 7 device profile

Both projects explicitly set `browserName: chromium` so the CI dependency surface matches the browser installed by the workflow.

Required common gate:

- no document-level horizontal overflow

Additional gates:

- `dense-tables`: wide table behavior is contained by a local horizontal scroller
- `forms-ime-errors`: labels, helper text, errors, and controls remain inspectable
- `mobile-wrap-stress`: marked actions keep at least 44px target height on the mobile project

Run locally:

```bash
npm install
npx playwright install chromium
npm run test:rendered
```

CI additionally installs Linux browser dependencies with:

```bash
npx playwright install --with-deps chromium
```

## Gate D — Evidence retention

Every rendered CI run must upload `rendered-validation-evidence` containing:

- `test-results/`
- full-page fixture screenshots
- JSON render metrics attached to tests
- Playwright HTML report
- retained traces for failures

CI artifact retention is currently 14 days.

A release candidate is not considered verified if rendered tests passed but the corresponding evidence artifact was not produced.

## Gate E — Documentation consistency

Before tagging the release:

- README status must match implemented behavior
- CHANGELOG must list the delivered v0.2 surface
- Agent Skill must reference the current validation workflow
- no item already implemented may remain described as future work

## Current v0.2 non-goals

These are useful extensions, but they are not blockers for the first v0.2 release:

- pixel-perfect screenshot baseline comparison
- Firefox and WebKit release gating
- automated visual-diff approval workflow
- `docs-prose-code` P2 fixture implementation
- package-manager distribution of the Python validator
- hosted gallery / GitHub Pages

## Release decision

`v0.2.0` may be tagged only when Gates A through E are satisfied on the release candidate commit.

A green status means the current contract surface is **testable and evidenced**. It does not mean every possible Japanese UI is covered. New real-world failures should enter through the broken-output flow and be promoted into a fixture, validator rule, profile change, or implementation fix as appropriate.
