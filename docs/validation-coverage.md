# 何を検査できるか

検査結果のPASSは、実行した検査の範囲にだけ適用します。契約ファイルの整合性、検証用HTMLの動作、利用者自身の画面は別の対象です。

## 検査の対応

| 対象 | コマンド・検査 | 自動化している範囲 | 残る確認 |
|---|---|---|---|
| DESIGN.md | `python validators/contract.py validate ...` | Locale / Profile / Review status、Validation Targetsの存在、CSSコードブロック内のbreak-all検出 | 指定値の妥当性、実装への適合、実際に誰がレビューしたか |
| 厳格モード | `validate --strict ...` | 上記に加えてValidation Targetsが3件以上あること | 項目数は検査の実施・網羅性を証明しない |
| 固定fixture | `npm run test:rendered` | 7種類のfixture、デスクトップChromiumとPixel 7設定のChromium、横はみ出しと一部の構造条件 | 利用者のアプリ、Firefox / WebKit、実機、全状態 |
| 利用者の画面 | `npm run check:ui -- --url ...` | 指定したローカルURL・画面幅での文書全体の横はみ出し | 契約への適合、部品内部の欠け、見た目、操作性 |
| 表・コード | fixture内の指定要素 | overflow-xがauto / scrollであること、対象が表示されること | 任意の表の自動認識、内容の読みやすさ |
| タップ対象 | mobile-wrap-stress内の指定要素 | モバイル設定で高さ44px以上 | 幅、間隔、全操作要素、アクセシビリティ全般 |
| 日本語フォーム | forms-ime-errors | 指定ラベル・補足・エラー・コントロールが表示されること | 実際のIME変換、候補表示、フォーカス操作 |
| 読みやすさ・和欧混植・配色 | scorecardと目視 | 自動合否には含めない | 実フォント、改行、コントラスト、内容と用途に沿った判断 |

## 利用者URLの検査仕様

`validators/overflow.mjs`はChromiumで指定ページを開き、次の条件を検査します。

`document.documentElement.scrollWidth <= document.documentElement.clientWidth + 1`

許容差は1 CSS pxです。既存fixtureの文書全体の横はみ出し検査と同じ基準です。フォント、本文行間、契約のValidation Targetsを読み取って判定する機能ではありません。

- 入力URLはHTTP(S)のlocalhost / 127.0.0.1 / [::1]に限定します。自身のアプリを起動した上で指定してください。
- ページのload完了、可視の待機要素、フォント読み込み完了を待ちます。SPAは実画面の準備完了を示す`--ready-selector`を指定してください。既定のbody表示だけでは、すべての非同期データの準備完了を保証しません。
- 既定は412 × 839 CSS px。これはデスクトップChromiumの表示幅変更であり、Pixel 7の実機やモバイルエミュレーションではありません。
- 画面幅・高さは240〜4096、各待機のタイムアウトは100〜120000ms。`--timeout`は処理全体の時間上限ではありません。
- リンクの巡回、ログイン、ボタンクリック、フォーム送信は行いません。ページ自身のJavaScriptと通信は通常どおり実行されます。
- 同一origin内のリダイレクトは許可し、最終URLを記録します。別originへの移動はERRORです。ログインページへ同一origin内で移動するアプリでは、目的画面固有の待機要素も指定してください。
- 新規ブラウザを使用するため、普段使うブラウザのログイン状態は引き継ぎません。

## 終了コードとEvidence

| 結果 | 終了コード | 意味 |
|---|---|---|
| PASS | 0 | 測定した文書全体の横はみ出しが許容差以内 |
| FAIL | 1 | 測定した文書全体の横はみ出しを検出 |
| ERROR | 2 | 引数・起動・HTTP・待機・計測・保存などで検査が成立しない |

既定では`ui-evidence/run-*/`に実行ごとに新しいディレクトリを作成します。

- `report.json`：対象と最終URL、実行時刻、ブラウザバージョン、画面幅、実測値、判定、未検査項目
- `viewport.png`：その画面幅で見える範囲のスクリーンショット。横にはみ出した全内容を縮小して収める画像ではありません。

引数エラーや出力ディレクトリ作成失敗ではレポートを保存できません。ブラウザ起動・HTTP・待機エラーは、保存可能ならERRORレポートを残します。測定後に画像保存が失敗した場合も全体はERRORです。

出力先は`--output`で変更できます。URLや画面に業務情報が含まれる場合、Evidenceにも含まれます。リポジトリの`.gitignore`は既定の`ui-evidence/`を除外しますが、独自の出力先は自身で管理してください。

## PASSでも残る反例

`overflow: hidden`で部品内の文字を切り落とした画面は、文書全体が横に広がらなければPASSになります。これは「見切れがない」という検査ではありません。この限界を回帰テストでも明示しています。

また、縦スクロール下の内容、開いていないモーダル、入力後のエラー表示などは、その状態を用意しなければ評価できません。今回確認した画面と状態をレビュー記録へ記載してください。

## 契約と検査を増やすとき

DESIGN.mdを人間が編集する契約として維持します。自由記述の項目を、実装していない自動検査へ対応済みと扱わないでください。JSON exportは契約メタデータ等の投影であり、すべてのデザイン条件を実行する仕様ではありません。

新しい自動検査は、具体的な失敗例、判定対象、測定方法、未検査範囲をそろえて追加します。現在のv0.2.0公開記録や合格条件を後から書き換えません。
