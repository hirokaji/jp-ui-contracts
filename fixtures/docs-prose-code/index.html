Runtime Feedback Loopを実装するとき、Evidenceをどこへ戻すか

日本語本文・inline code・code block・callout・tableが同じ技術文書に共存するfixture

技術文書では、本文だけを読みやすくしても十分ではありません。たとえば failure_attribution のような英語識別子や設定名が日本語文中に入り、直後に長いコード例が続くと、本文のリズムとコードの密度が衝突します。

重要なのは、本文・コード・補足・表を同じ密度で扱わないことです。本文は持続して読める必要がありますが、コードは正確な文字列を保ち、表は走査性を優先します。

設定例 — Evidenceから変更候補を作る

feedback:
  evidence_source: runtime/evidence/latest.json
  failure_attribution: contract_boundary
  change_target: evaluation_rule
  require_human_approval: true
  exceptionally_long_machine_identifier: runtime_evidence_failure_attribution_change_candidate_20260914_example
注意 コードの横幅を本文側の改行規則で無理に折り返すと、コピー可能性や識別子の正確性を壊すことがあります。長いコードは、文書全体ではなくコード領域内へoverflowを封じ込めます。
